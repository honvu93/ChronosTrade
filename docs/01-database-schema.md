# Database Schema Reference — Disaster Recovery Document

> Generated 2026-04-14. Authoritative source: `prisma/schema.prisma` + `prisma/migrations/`.

---

## 1. Database Overview

| Database | Engine | Port | Purpose |
|---|---|---|---|
| **Main** | TimescaleDB (PostgreSQL + timescaledb extension) | `:5433` | All platform data: candles (hypertable), signals, backtests, trading accounts, positions, orders, deals, execution commands, users, indicator instances, optimization jobs, webhook deliveries |
| **External Signal** | PostgreSQL | `:5434` | Isolated database for external signal deployments (Telegram, webhooks). Uses `EXTERNAL_SIGNAL_DB_URL`. Schema is NOT in this Prisma file — managed separately by the `externalAction` service. |

Both databases run inside Docker Compose. The main database URL is configured via `DATABASE_URL` in `.env`.

## 3. Models

### 3.1 Candle

**Table:** `price_candles` | **Purpose:** OHLCV price data. This is a **TimescaleDB hypertable** partitioned by `time`.

| Field | Type | Constraints | Description |
|---|---|---|---|
| `time` | `DateTime` | **PK (composite)**, required | Candle open timestamp |
| `symbol` | `String` | **PK**, VarChar(20), required | Trading instrument (e.g., `XAUUSD`, `BTCUSDT`) |
| `timeframe` | `String` | **PK**, VarChar(10), required | Candle interval (e.g., `1m`, `5m`, `1h`, `4h`, `1d`) |
| `exchange` | `String` | **PK**, VarChar(20), required | Data source (e.g., `binance`, `mt5`) |
| `open` | `Decimal(20,8)` | required | Opening price |
| `high` | `Decimal(20,8)` | required | Highest price |
| `low` | `Decimal(20,8)` | required | Lowest price |
| `close` | `Decimal(20,8)` | required | Closing price |
| `volume` | `Decimal(20,8)` | required | Base asset volume |
| `quote_volume` | `Decimal(20,8)` | optional | Quote asset volume |
| `trades` | `Int` | optional | Number of trades in candle |
| `taker_buy_volume` | `Decimal(20,8)` | optional | Taker buy volume |
| `is_closed` | `Boolean` | default: `true` | Whether candle is finalized |

**Primary Key:** Composite `(time, symbol, timeframe, exchange)`

**Additional Index (from SQL):** `idx_candles_symbol_timeframe` on `(symbol, timeframe, time DESC)` -- optimizes queries for "latest N candles of XAUUSD on 1m".

**Relations:** None (standalone time-series table).

**Special:** Managed outside Prisma migrations via `01_init_timescaledb.sql`. See Section 6 for TimescaleDB features.

| `entryTime` | `DateTime` | required | When the signal triggered |

| `takeProfit1` | `Decimal(20,8)` | optional | First take-profit target |

**Indexes:**

| Index | Fields | Purpose |
|---|---|---|

| 2 | `(sourceType, definitionCode, definitionVersion)` | Filter signals by definition and source |

| 4 | `(strategyId, session)` | Performance breakdown by strategy and session |

**Indexes:**

## 4. Data Flow Relationships

### 4.1 Signal Lifecycle

```
SignalDefinition (code + version)
    |
    v
BacktestRun (uses signal definition parameters)
    |
    +---> Signal[] (generated or imported signals)
    |        |
    |        +---> BacktestTradeResult[] (via ExitRule)
    |        +---> SignalEvent[] (lifecycle events: TRAP -> ENTRY -> TP1_HIT ...)
    |                 |
    |                 +---> SignalLogicTrace (1:1, debug info)
    |
    +---> SignalOptimizationRun (if part of optimization)
             |
             v
         SignalOptimizationJob (parent job with parameter space)
```

### 4.2 Live Indicator Pipeline

```
SignalDefinition (code + version)
    |
    v
IndicatorInstance (running on symbol:timeframe, processing candles)
    |
    +---> SignalEvent[] (live events emitted)
    |        |
    |        +---> SignalLogicTrace (debug)
    |        +---> TradingTradeIntent (if automation binding exists)
    |
    +---> IndicatorAlert[] (user-defined alerts)
    +---> TradingAutomationBinding[] (links to trading accounts)
```

### 4.3 Trading Lifecycle

```
User
  |
  +---> TradingAccount (with Mt5Credential)
           |
           +---> TradingAutomationBinding (links IndicatorInstance to account)
           |        |
           |        v
           |     TradingTradeIntent (created when signal event fires)
           |        |
           |        v
           |     TradingExecutionCommand (built from intent after risk checks)
           |        |
           |        +---> TradingExecutionEvent[] (audit log)
           |        |
           |        v
           |     [MT5 Bridge :8766] --> Broker
           |
           +---> TradingSyncRun (reconciliation)
           |        |
           |        v
           +---> TradingPosition[] (synced from broker)
           +---> TradingOrder[] (synced from broker)
           +---> TradingDeal[] (synced from broker)
           +---> TradingAccountSnapshot[] (periodic equity snapshots)
```

### 4.4 User/Auth Model

```
User
  |
  +---> UserModuleAccess[] (per-module permissions)
  +---> TradingAccount[] (owned accounts)
  +---> activeTradingAccount (currently selected, FK)
```

## 5. TimescaleDB-Specific Features

### 5.1 Hypertable

The `price_candles` table is converted to a TimescaleDB hypertable, partitioned by the `time` column:

```sql
SELECT create_hypertable('price_candles', 'time', if_not_exists => TRUE);
```

### 5.2 Compression Policy

Chunks older than 7 days are automatically compressed, segmented by `symbol` and `timeframe`:

```sql
ALTER TABLE price_candles SET (
  timescaledb.compress,
  timescaledb.compress_segmentby = 'symbol, timeframe'
);
SELECT add_compression_policy('price_candles', INTERVAL '7 days');
```

### 5.3 Continuous Aggregates

Nine materialized views aggregate 1-minute candles into higher timeframes. All use the `time_bucket` function with `first(open, time)`, `max(high)`, `min(low)`, `last(close, time)`, and `sum(volume)`.

| View | Bucket | Source | Refresh Interval | Start Offset | End Offset |
|---|---|---|---|---|---|
| `candles_5m` | 5 min | `price_candles` (1m) | 5 min | 1 hour | 5 min |
| `candles_15m` | 15 min | `price_candles` (1m) | 15 min | 6 hours | 15 min |
| `candles_30m` | 30 min | `price_candles` (1m) | 30 min | 12 hours | 30 min |
| `candles_1h` | 1 hour | `price_candles` (1m) | 1 hour | 1 day | 1 hour |
| `candles_4h` | 4 hours | `price_candles` (1m) | 4 hours | 3 days | 4 hours |
| `candles_12h` | 12 hours | `price_candles` (1m) | 12 hours | 1 week | 12 hours |
| `candles_1d` | 1 day | `price_candles` (1m) | 1 day | 1 month | 1 day |
| `candles_3d` | 3 days | `price_candles` (1m) | 3 days | 3 months | 3 days |
| `candles_1w` | 1 week | `price_candles` (1m) | 1 week | 6 months | 1 week |
| `candles_1M` | 1 month | `price_candles` (1m) | 1 month | 1 year | 1 month |

### 5.4 Custom Index

```sql
CREATE INDEX idx_candles_symbol_timeframe ON price_candles (symbol, timeframe, time DESC);
```

Optimizes the most common query pattern: "get latest N candles for XAUUSD on 1m timeframe".

## 8. Reconstruction Checklist

To rebuild the database from scratch:

1. **Start TimescaleDB** container on port 5433.
2. **Run** `01_init_timescaledb.sql` to create the hypertable and compression policy.
3. **Run** `02_continuous_aggregates.sql` to create all continuous aggregate views.
4. **Run** `npx prisma migrate deploy` to apply all Prisma migrations in order.
5. **Start external PostgreSQL** on port 5434 for the external signal database (separate schema, not in this Prisma file).
6. **Seed** `strategies` and `exit_rules` with your strategy codes.
7. **Seed** `signal_definitions` with your signal definitions.
8. **Seed** `tech_indicator_definitions` with indicator catalog entries.
9. **Create** admin user via API or direct insert.
10. **Restore** candle data from backup (this is the largest dataset).
